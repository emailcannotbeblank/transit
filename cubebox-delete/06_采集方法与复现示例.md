## 5. CubeMaster CLI `multirun`

用途：直接访问 CubeMaster `/cube/sandbox`，排除 CubeAPI/SDK。

请求配置：`configs/cubemaster_request.json`

```bash
cd /home/zry/桌面/0702/0725

cubemastercli \
  --address 127.0.0.1 \
  --port 8089 \
  --timeout 360s \
  multirun \
  --runcnt 1 \
  --runcc 10 \
  --delcc 10 \
  --same \
  --printall \
  configs/cubemaster_request.json

cubemastercli --address 127.0.0.1 --port 8089 list
```

配置注意：

- 必须带 `cube.master.appsnapshot.template.version=v2`，否则请求会进入旧的本地模板路径；
- v2 请求只传模板 annotation，不应再附带已经解析出的 template volume/container，否则会重复合并 `cube_rootfs_rw`。

本次结果：

```text
create: 10/10
destroy: 10/10
CLI removeMetric: min 94, p50 121, p99 139 ms
post list: 0
```

原始输出：

- `raw/tool-examples/cubemaster-cli/stdout.txt`
- `raw/tool-examples/cubemaster-cli/post-list.txt`
- `raw/tool-examples/cubemaster-cli/attempt-minimal-request-failed.txt`

当前 CLI 会把每次成功销毁的 `clientReqCost` 写两次，所以 10 次请求打印 20 个重复值。`--delcc` 在材料所分析的源码中也没有实际 acquire/release；它不能提供严格 delete barrier。

## 6. Cubelet CLI `multirun`

用途：直连 Cubelet，获得 Destroy response 的全部 ext_info，是当前最直接的节点级阶段采集。

本机 Cubelet Unix socket 仅 root 可连接，CLI 的自定义 address 走 Unix dialer。使用 `socat` 把一个当前用户可访问的临时 Unix socket桥接到本机 TCP `127.0.0.1:9999`：

```bash
cd /home/zry/桌面/0702/0725

bridge_dir=$(mktemp -d /tmp/cubelet-cli.XXXXXX)
bridge_socket="$bridge_dir/cubelet.sock"
socat UNIX-LISTEN:"$bridge_socket",fork TCP:127.0.0.1:9999 &
bridge_pid=$!

cubecli \
  --address "$bridge_socket" \
  --timeout 360s \
  multirun \
  --addrm \
  --runcnt 1 \
  --runcc 10 \
  --delcc 10 \
  --same \
  --printall \
  configs/cubelet_request.json

cubecli --address "$bridge_socket" cubebox list
kill "$bridge_pid"
```

配置注意：Cubelet CLI 使用 Go `encoding/json` 解析生成的 protobuf struct，`EmptyDirVolumeSource` 的字段名是 `SizeLimit`，不是 Master HTTP JSON 使用的 `size_limit`。

本次结果：

```text
create: 10/10
destroy: 10/10
clientReqCost: min 73, p50 87, p99 111 ms
cubebox:       min 69, p50 83, p99 97 ms
storage:       min 0,  p50 1,  p99 2 ms
network:       min 0,  p50 1,  p99 2 ms
post list: 0
```

原始输出：

- `raw/tool-examples/cubelet-cli/stdout.txt`
- `raw/tool-examples/cubelet-cli/post-list.txt`

限制：它绕开 CubeAPI/CubeMaster，不能代表用户端总时延；`delcc` 是并发上限，不是所有 DELETE 的统一 barrier。

## 7. 严格 CREATE barrier + DELETE barrier

单独运行生命周期用例：

```bash
cd /home/zry/桌面/0702/0725

conda run -n pytorch python tools/lifecycle_destroy_case.py \
  --count 10 \
  --template "$CUBE_TEMPLATE_ID" \
  --settle-seconds 1 \
  --sandbox-timeout 300 \
  --request-timeout 120 \
  --verify-timeout 10 \
  --output raw/my-strict-run/lifecycle.json
```

JSON 包含：

- CREATE 和 DELETE 每请求 latency；
- barrier release 的 UTC/epoch 时间；
- worker start skew；
- 整轮 wall time 和吞吐；
- created/destroyed/residual IDs；
- 失败清理和最终 list 错误。

## 8. 一键全量观测

入口：`tools/run_observability_example.sh`

```bash
cd /home/zry/桌面/0702/0725

COUNT=10 \
PROM_INTERVAL=0.1 \
tools/run_observability_example.sh \
  /home/zry/桌面/0702/0725/raw/my-observed-run
```

该脚本同时采集：

| 类别 | 文件/数据 |
|---|---|
| 客户端 E2E | `lifecycle.json`、`lifecycle.stdout.txt` |
| CubeMaster | 请求窗口、内部 Cubelet Destroy response |
| Cubelet | req/stat 日志、Destroy ext_info |
| CubeShim | req/stat、Kill/Wait/Delete/Shutdown/VM join |
| VMM | `CubeVmm-vmm.log` |
| network-agent | ReleaseNetwork 日志 |
| CubeCoW | RPC before/after；日志存在时截取日志窗口 |
| Prometheus | 全量 before/after、时间序列 JSONL、并发峰值 |
| pprof | CPU、trace、heap、goroutine、mutex、block |
| 系统 | iostat、pidstat、mpstat、vmstat |
| 收敛 | Master/Cubelet list、storage、network state、进程、Redis proxy key |
| 后处理 | `destroy-breakdown.json/csv`、`system/summary.json` |

脚本按采集开始时每个组件日志的 byte offset 截取窗口，避免把历史运行混入当前样本。

## 9. 销毁日志关联与拆解

手工重跑后处理：

```bash
python3 tools/analyze_destroy_logs.py \
  --report raw/my-observed-run/lifecycle.json \
  --master-req raw/my-observed-run/logs/CubeMaster-cubemaster-req.log \
  --cubelet-stat raw/my-observed-run/logs/Cubelet-Cubelet-stat.log \
  --shim-req raw/my-observed-run/logs/CubeShim-cube-shim-req.log \
  --shim-stat raw/my-observed-run/logs/CubeShim-cube-shim-stat.log \
  --output-json raw/my-observed-run/destroy-breakdown.json \
  --output-csv raw/my-observed-run/destroy-breakdown.csv
```

处理器会：

- 只保留 lifecycle report 中的 sandbox ID；
- 解码 Master 内部日志中 base64 的 Cubelet ext_info；
- 合并 Cubelet stat；
- 按同 sandbox ID 的时间序列计算 Shim 阶段差；
- 使用 `max(storage, network, ...)` 表示并行资源阶段；
- 输出逐样本 JSON/CSV 和分位数。

```bash

  -v "$PWD:/work" \
  -w /work \
  cube-sandbox-builder:ubuntu2004-clang12 \
  sh -c 'go tool trace -pprof=sched trace.out > trace-sched.pprof'

```

Cubelet list
Redis proxy key EXISTS
network-agent allocation state
